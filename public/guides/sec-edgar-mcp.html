How to research a US company with SEC EDGAR in Claude or Cursor using MCP

Written by the maintainer of edgar-entity-mcp (disclosure: this guide is about the maintainer's own open-source project). Last updated: 2026-10-29.

TL;DR: Add one MCP server, edgar-entity-mcp, to Claude Desktop, Claude Code, Cursor or VS Code. Your AI assistant can then look up a company in SEC EDGAR: filings, 10-K sections, XBRL financials, Form 4 insider transactions and peer comparisons. It can also check state Secretary of State business registries (NY, CO, OR, CT, PA). Every answer includes source URLs so you can check it. The hosted endpoint is a free beta with low limits and no API key, and the code is MIT-licensed.

Not investment, legal or financial advice. edgar-entity-mcp is not affiliated with or endorsed by the SEC or any state agency, is not a consumer reporting agency, and must not be used for FCRA purposes (credit, employment, insurance or tenant screening). State data covers only the listed states and datasets and may be incomplete or delayed.

What you'll be able to ask

  • "Find Apple's CIK and show its latest 10-K."
  • "Summarize the Risk Factors (Item 1A) of Apple's latest 10-K."
  • "Show Apple's revenue, net income and free cash flow for the last fiscal year, with the XBRL tags used."
  • "Compare Ford, GM and Tesla on revenue for calendar year 2023."
  • "List the last five Form 4 filings for Tesla and explain the transaction codes."
  • "Is Newmont Corporation registered in Colorado? What is its status and registered agent?"

What you need

  • An MCP-capable client: Claude Desktop, Claude Code, Cursor, Windsurf or VS Code (all listed in the project README).
  • Either nothing else, for the hosted remote endpoint (recommended), or Git and Node.js to run the server locally from the GitHub source over stdio. Use a current, patched Node.js: 22.23.4+ (22.x) or 24.22.1+ (24.x); the server warns on startup when Node.js is unpatched. The old npm package (0.1.0) is deprecated and no longer maintained; do not install it.

Step 1: Connect the server

Option A: Hosted endpoint (no install, no key)

Add this to your client's MCP config:

{ "mcpServers": { "edgar-entity": { "url": "https://edgar-entity-mcp.vercel.app/mcp" } } }

If your client only speaks stdio, use the mcp-remote bridge:

{ "mcpServers": { "edgar-entity": { "command": "npx", "args": ["-y", "mcp-remote", "https://edgar-entity-mcp.vercel.app/mcp"] } } }

Option B: Run locally from the GitHub source (stdio)

git clone https://github.com/pgeneralpl/edgar-entity-mcp.git
cd edgar-entity-mcp
npm ci && npm run build

Then add it to your client's MCP config, using the absolute path of your clone:

{
  "mcpServers": {
    "edgar-entity": {
      "command": "node",
      "args": ["/absolute/path/to/edgar-entity-mcp/dist/stdio.js"],
      "env": { "SEC_USER_AGENT": "Your Name you@example.com" }
    }
  }
}

For local use, the SEC's fair-access policy asks automated clients to identify themselves, so set SEC_USER_AGENT to your name and a contact email.

Where the config lives:

  • Claude Desktop: ~/Library/Application Support/Claude/claude_desktop_config.json (macOS) or %APPDATA%\Claude\claude_desktop_config.json (Windows).
  • Cursor: ~/.cursor/mcp.json (global) or .cursor/mcp.json (project).
  • Claude Code: claude mcp add --transport http edgar-entity https://edgar-entity-mcp.vercel.app/mcp (hosted) or claude mcp add edgar-entity -e SEC_USER_AGENT="Your Name you@example.com" -- node /absolute/path/to/edgar-entity-mcp/dist/stdio.js (local)
  • VS Code: .vscode/mcp.json, using "servers" instead of "mcpServers".

Restart the client. You should see 10 tools from edgar-entity.

Step 2: Find the company (ticker → CIK)

EDGAR identifies filers by CIK (Central Index Key). Ask: "Search EDGAR for Berkshire." The assistant calls search_company:

search_company {"query":"berkshire"} → BERKSHIRE HATHAWAY INC, CIK 0001067983, tickers BRK-B, BRK-A.

All other tools accept a ticker (AAPL), a CIK (320193) or an unambiguous name. If a name is ambiguous, the server returns candidate CIKs.

Step 3: Get the profile and filings

  • get_company_profile returns name, tickers, exchanges, SIC code and industry, state of incorporation, fiscal year end, addresses, former names, and the latest 10-K/10-Q.
  • list_filings filters by form type (10-K, 10-Q, 8-K…) and date range, and returns accession numbers and document URLs. Example: {"company":"AAPL","forms":["10-K"],"date_to":"2010-12-31","limit":2} returns the 2010 10-K and 10-K/A.

Step 4: Read the parts of a filing that matter

get_filing_document converts the primary document to clean text and can extract 10-K/10-Q items: 1 (Business), 1A (Risk Factors), 7 (MD&A), 7A, 8 and so on. Long text is paged with max_chars and offset.

{"url":"https://www.sec.gov/Archives/edgar/data/320193/000032019325000079/aapl-20250927.htm","section":"1A","max_chars":3000}

Prompt idea: "Read Item 1A of Apple's latest 10-K and list the five risks that are new or changed compared to the prior year, quoting the filing."

Tip: filing text is written by the filer and is treated as untrusted data. The hosted server wraps it in explicit markers so that well-behaved agents don't follow instructions hidden inside documents.

Step 5: Pull normalized financials (with the XBRL tags used)

get_financials {"company":"AAPL","limit":1} returns one row per fiscal period: revenue, gross profit, operating income, net income, EPS, assets, liabilities, equity, cash, long-term debt, operating cash flow, capex, derived free cash flow and shares outstanding. It also returns tags_used, so you can see which XBRL concept each number came from. A trimmed excerpt from the README:

{"name":"Apple Inc.","period_type":"annual",
 "periods":[{"fy":2025,"form":"10-K","filed":"2025-10-31","revenue":416161000000,"net_income":112010000000,
   "operating_cash_flow":111482000000,"capex":12715000000,"free_cash_flow":98767000000}],
 "tags_used":{"revenue":["us-gaap:RevenueFromContractWithCustomerExcludingAssessedTax"]},
 "source_url":"https://data.sec.gov/api/xbrl/companyfacts/CIK0000320193.json"}

Here free cash flow is operating cash flow minus capex (111,482M − 12,715M = 98,767M). Use period_type:"quarterly" for 3-month values. When quarters have to be derived (for example Q4 = FY − 9M), the response says so in notes.

Need one specific line item over time? get_xbrl_concept {"company":"TSLA","tag":"ResearchAndDevelopmentExpense","forms":["10-K"]}.

Step 6: Compare companies on one metric

compare_companies uses SEC XBRL "frames" (one concept across all filers for one period):

{"tag":"Revenues","period":"CY2023","companies":["TSLA","F","GM"]}

Per the README sample output: Ford $176.19B, GM $171.84B and Tesla $96.77B for CY2023, each with its rank among the 2,679 companies reporting that tag. Balance-sheet (point-in-time) concepts need an I suffix, e.g. CY2024Q4I.

Caveat: companies don't always use the same tag (for example Revenues vs RevenueFromContractWithCustomer…). Check tags_used before you draw conclusions.

Step 7: Insider transactions (Form 4), in plain English

get_insider_trades {"company":"TSLA","limit":5} parses Form 4/4A filings and returns the reporter, their role or title, the transaction code with its plain-English meaning (e.g. S = open market or private sale, M = exercise or conversion of a derivative, F = shares withheld for exercise price or taxes), shares, price, value, holdings after the transaction, and a buy/sell summary, each with a link to the filing.

Insider transactions have many routine explanations, such as tax withholding, planned sales and option exercises. Treat them as facts to read, not signals to trade on.

Step 8: Check a private or state-registered entity (Secretary of State)

Many companies, including LLCs and private suppliers, never file with the SEC. lookup_business_entity searches official state open-data registries by name or entity ID:

{"name":"Newmont Corporation","states":["CO"]}

returns status ("Good Standing"), type, formation date, jurisdiction of formation (DE), principal address, registered agent (when it is a company), and links to the state record.

Coverage (call list_supported_states for the current details and licenses):

State Records
New York, Oregon, Pennsylvania active entities only
Colorado, Connecticut include dissolved / inactive entities

Not covered: every other state, including Delaware, California, Florida and Texas. "Not found" therefore does not mean that an entity doesn't exist. The hosted endpoint does not return the names or addresses of registered agents who are individuals. The deprecated npm package 0.1.0 does not filter these fields; do not use it.

A complete research prompt

"Research Newmont Corporation: find its CIK and industry, summarize the latest 10-K's business description in five bullets, show the last three fiscal years of revenue, net income and free cash flow with the XBRL tags used, list any Form 4 filings from the last 90 days with what each code means, and check its Colorado registration. Cite a source URL for every fact."

The server also ships a company_research_brief prompt that runs a similar workflow.

Limits (free beta)

The hosted endpoint is a free beta with low limits, intended for interactive research, not bulk downloads.

  • Usage is measured in units; a cached call usually costs 1 unit.
  • Currently up to 60 units per day per IP (shared networks may get less) and 30 per minute; limits may change without notice.
  • Heavier tools cost more units (for example, Form 4 lookups and full documents).
  • If you need more, run it locally from the GitHub source over stdio (Option B above) and set SEC_USER_AGENT to your own name and email. Local stdio use has no unit quotas; self-hosted HTTP mode (npm run start:http) enforces quotas like the hosted endpoint. The local server still has to respect the SEC's fair-access limit (10 requests per second), so it throttles its SEC requests to 6 per second by default (SEC_MAX_RPS).

FAQ

Is this free? Yes. The hosted endpoint is a free beta with low daily limits and no signup or API key, and the code is open source under the MIT license.

Do I need an SEC API key? No. SEC EDGAR's APIs are public. If you run the server locally, set SEC_USER_AGENT to your name and email, as the SEC's fair-access policy asks.

Which AI clients work? Any MCP client. The README documents Claude Desktop, Claude Code, Cursor, Windsurf and VS Code, plus a remote Streamable HTTP endpoint and an mcp-remote fallback for stdio-only clients.

What data sources does it use? SEC EDGAR (data.sec.gov submissions, XBRL companyfacts, companyconcept and frames, plus www.sec.gov/Archives documents and Form 4 XML) and the official open-data (Socrata) business registries of New York, Colorado, Oregon, Connecticut and Pennsylvania.

Is it affiliated with the SEC or a state? No. It is an independent open-source project that reads public data. It is not affiliated with or endorsed by the SEC or any state agency.

Does it cover Delaware? No. Only NY, CO, OR, CT and PA are covered right now, and NY/OR/PA include active entities only.

Can I use it for background checks, credit, employment or tenant screening? No. It is not a consumer reporting agency, and it must not be used for any FCRA purpose.

Is this investment, legal or financial advice? No. It is not investment, legal or financial advice. It returns public filings and registry data with links to the source. Always verify the figures in the original filing.

How fresh is the data? EDGAR data is fetched from the SEC with short caches (about 10 minutes for filing lists, a few hours for XBRL facts). State datasets update on each state's own schedule, which list_supported_states reports.

Can I self-host it? Yes. npm run build && npm run start:http runs the HTTP server locally, and the repo includes a Vercel deployment config. Self-hosted HTTP mode enforces per-IP quotas like the hosted endpoint (defaults adjustable with the QUOTA_* environment variables); only local stdio use has no quotas. Set SEC_USER_AGENT to your own name and email.

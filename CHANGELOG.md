# Changelog

## 0.2.0 (unreleased)

- **Search usability (`search_company`, `lookup_business_entity`):**
  - `search_company`: names are normalised (case, punctuation, `&` = `and`, Inc/Inc./Incorporated, Corp/Corporation, Co/Company, LLC/L.L.C., Ltd/Limited, leading "The") and matched typo-tolerantly with a bounded edit distance over the **cached** ticker list (no extra SEC request per query): `Microsfot` → MSFT, `berkshre hathaway` → BRK. Typo matches score below 80, so a typo'd `company` argument on other tools returns `AMBIGUOUS` with the candidate instead of resolving silently. A curated list of ~25 well-known former names (`src/sec/formerNames.ts`: Facebook, Google, Apple Computer, Wal-Mart, Philip Morris…) is matched as well and reported as `matched_former_name`. With no match the result (and the `NOT_FOUND` error of every `company` argument) carries `did_you_mean`, a hint to use `lookup_business_entity` for private/non-SEC companies, and an `edgar_company_search_url` link (EDGAR company search over current and former names; a link, not a call).
  - `lookup_business_entity`: server-side relevance order (`$order`): exact name in any spelling variant (`&`/`AND`, suffix spellings, comma before the suffix, leading THE; max 32 variants) > prefix > other matches, then active before inactive (CO, CT), then name; re-ranked the same way within the page. LIKE patterns use only the distinctive A–Z/0–9 tokens in order (`Tiffany and Company` → `%TIFFANY%`), so `TIFFANY AND COMPANY` and `TIFFANY & CO.` match each other; `match: "exact"` matches any spelling variant. New `offset` (0–500) and `include_total` inputs; results report `count`, `offset`, `has_more`, `next_offset`, `total` (with `include_total`, or on the last page) overall and per state, plus `active_only_dataset` (NY, OR, PA) and an `active_only_note`. Pages are fetched with `$limit = limit + 1` (precise `has_more`); Oregon (row per associated name) is grouped over a window of at most 300 rows.
  - *Cost / limits (security review):* `include_total` adds one `count(*)` / `count(distinct id)` request per state, so its cost is 2 × states (max 10 units, was max 5). Each page is a separate cached request (`TTL.stateSearch`, existing cache budget), rate-limited by the existing Socrata limiter. Inputs stay bounded: `offset` ≤ 500, `limit` ≤ 25 per state, ≤ 5 states, names ≤ 200 chars; edit distance capped at 64 chars per token; EDGAR search link query ≤ 100 chars. Oregon windows are 300 rows max (previously 200).
  - Deferred: SEC filers without a ticker (the full ~900k-name `cik-lookup-data.txt` is too large for the cache budget); EDGAR `formerNames` are not fetched per query (they would cost one submissions request per candidate), hence the curated list plus the EDGAR search link.
- **Filing documents and structured output (usability backlog, PR C):**
  - `get_filing_document`: new `mode: "outline"` returns the detected 10-K/10-Q items (`id`, `title`, `offset`, `chars`) and `total_chars` with no text, so agents can plan reads of long filings; default `max_chars` 20,000 → 10,000 (range unchanged, 500–100,000; `offset` 0–20,000,000). Item titles follow the form (company mode uses the filing's form; url mode reads "FORM 10-K/10-Q" from the cover page), so item 2 of a 10-Q is "MD&A", not "Properties". By `url` the response now also has `cik`, `accession` and `index_url`, parsed from the validated Archives path (no extra request; form and filing date still need `company` + `accession`). Clearer description: one of `url` or `company` + `accession` is required, and how offsets work. Cost unchanged (4 by url, 10 by company + accession).
  - Every tool declares an `outputSchema` and successful results include `structuredContent` (identical to the JSON text, which is kept for older clients). Permissive schemas (nullable fields, extra fields allowed) so unusual upstream data can't fail validation; validated in tests against real production outputs.
  - `company_research_brief` prompt: the entity-lookup step now names the supported states (NY, CO, OR, CT, PA), uses the state of incorporation when supported, else the HQ state, and says Delaware and California registries are not available (report it as a data gap rather than guessing).
  - HTTP: SSE responses are sent as `text/event-stream; charset=utf-8` (was no charset, which made some clients mis-decode `’` and other non-ASCII text). JSON responses unchanged.
- **Financials usability (`ux-financials`):**
  - `compare_companies` gets `metric` (exactly one of `metric` / `tag`): `revenue`, `net_income`, `gross_profit`, `operating_income`, `eps_basic`, `eps_diluted`, `operating_cash_flow`, `capex`, `total_assets`, `total_liabilities`, `stockholders_equity`, `cash`, `long_term_debt` plus aliases (`sales`, `revenues`, `turnover`, `profit`, `eps`, …). Up to 3 XBRL tags per metric are tried (`SalesRevenueNet` only for periods ≤ 2018); each company's first tag with data wins and every row reports its `tag`; `tags_tried`, `tags_used`, `companies_per_tag`. With `companies`, tags are fetched one by one and stop once all are found. Instant metrics get the `I` period suffix automatically; duration metrics reject `…I` periods. `unit` defaults to the metric's unit.
  - Calendar basis made explicit: `period_basis: "calendar"`, per-row `fiscal_period_differs` (> 14 days off the calendar period), notes on how frames pick fiscal periods and on `accn`; tag mode suggests `metric` when requested companies are missing under a tag that has known alternatives.
  - `get_financials`: `metrics` accepts the same aliases (max 20, deduped); `period_basis: "fiscal"`, `fiscal_year_end` (MM-DD); `hint` when the requested period type is empty but the other exists (e.g. a recent IPO with only 10-Qs); derived Q4 rows now carry `period_start` (day after the Q3 10-Q end).
  - `get_xbrl_concept`: `duration` filter (`any` / `annual` / `quarterly` / `ytd` / `instant`), per-fact `duration`, a note when durations are mixed; tag case corrected (`netincomeloss` → `NetIncomeLoss`, `tag_corrected_from`) for known tags without an extra request, otherwise via `companyfacts` after a 404; unknown tags return `NOT_FOUND` with `did_you_mean` (up to 5, from the company's own tags).
  - Quota: `get_xbrl_concept` reserves 3 (charged 1 on the direct path, refunded); `compare_companies` with `metric` reserves 3 × tags (max 9). All new requests go through the SEC limiter and the existing cache (frames 12 h, companyconcept/companyfacts 6 h).
  - Deferred: a fiscal-year basis for `compare_companies` (needs one `companyfacts` download per company; use `get_financials`).
- **Guide page:** `public/guides/sec-edgar-mcp.html`, served at `/guides/sec-edgar-mcp` (`cleanUrls`): the approved tutorial "How to research a US company with SEC EDGAR in Claude or Cursor using MCP" as static HTML with canonical URL and JSON-LD (TechArticle, HowTo, SoftwareApplication, FAQPage). Inline `<style>` only, no scripts besides inert JSON-LD and no external resources; `vercel.json` applies the strict HTML CSP to the new path. Test: `tests/guide.test.ts`.
- **Limit hints point at a GitHub issue form (no more "request a free API key"):** quota `RATE_LIMITED` errors (per-minute, per-day, per-network, global, API-key quotas) and the HTTP 401 for an invalid key now end with "Higher limits on the hosted endpoint may be requested by a person at https://github.com/pgeneralpl/edgar-entity-mcp/issues/new?template=higher-limits.yml (requests are reviewed manually and may be declined; please do not file automatically)." The key-required 401 (`MCP_REQUIRE_API_KEY=1`) says "An API key is required on this server. The link is one constant (`HIGHER_LIMITS_ISSUE_URL` in `src/config.ts`); a `KEY_REQUEST_URL` override is accepted only as an absolute https URL (otherwise the constant is used and a warning logged). Error codes, messages ("Invalid API key.", "An API key is required.") and `details` are unchanged; only `hint` texts change. New issue form `.github/ISSUE_TEMPLATE/higher-limits.yml` (label `higher-limits`; hobby-project disclaimer, no personal data or secrets, file it yourself, not via an AI agent). Privacy policy: new "GitHub issues" paragraph (GitHub as independent controller). API key support is unchanged.
- **Aggregate usage statistics (hosted server):** daily counters in Redis (`eem:v1:stats:YYYY-MM-DD:{c,u,cl}`, `EXPIREAT` end of the UTC day + 30 days): calls / ok / errors per tool, error codes, tier, latency histogram (approximate p50/p95), MCP sessions (`initialize`), client-software labels from a fixed allowlist of well-known MCP clients (major version only; anything else `other`; counted once per principal per day after its first successful tool call), degraded-mode activations, and approximate unique clients per day (HyperLogLog over `HMAC(random daily salt, principal id)`; the salt's TTL ends at 01:00 UTC the next day, after which no member is written for that day). Recorded only by Vercel production (`VERCEL_ENV=production`) or self-hosted servers (no `VERCEL`), never by previews. Aggregated in memory and written in small periodic fire-and-forget batches (never fails or slows a request; nothing written while degraded); a small, bounded number of keys. `STATS_ENABLED=false` turns it off. New `GET /stats?days=N` (1–30, default 7) gated by `STATS_SECRET` (`x-stats-secret`, constant-time; unset / wrong / missing → 404). Privacy policy and README updated.

Wording now says individual agents are *withheld (automated classification)* instead of *never returned*.

- **Post-launch hardening (MCP SEC Security audit, issue #5):**
  - `/health?deep=1` without a valid `x-health-secret` (or with `HEALTH_SECRET` unset) now returns **401** and no health data (was 200 with `deep: "skipped …"`). The authorised deep output adds `node_version` (`process.version`) and `node_runtime_patched`; `node_runtime_patched` is removed from the public `/health`.
  - Security headers in `vercel.json`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` on every path (including `/mcp` and `/health`), and on the HTML pages (`/`, `/privacy`, `/terms`, `/abuse`) `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` (the pages use inline `style` attributes and nothing else). No CSP on `/mcp` or `/health`.
  - Per-/24 (IPv6 /48) cap default: 4× the per-IP cap, still never more than 10% of the global anonymous budget: `min(4 × QUOTA_ANON_PER_DAY, 10% × QUOTA_ANON_GLOBAL_PER_DAY)`. With the current defaults (60/IP, 600 global) the 10% ceiling is lower and applies, so the effective cap stays 60; the 4× value (240) takes effect once the global budget is ≥ 2,400.
  - Docs: the quota-backend and SEC-limiter failure behaviour below now matches the code (Upstash failures degrade, they do not fail closed), and the C1 quota numbers are marked as superseded.

- **Redis cache limits (eviction off):** the Upstash database runs with eviction off (Upstash's only eviction policy evicts random keys and would reset quota counters), so the cache bounds itself: fleet-wide daily cache-write budget `CACHE_WRITE_BUDGET_BYTES` (default 64 MiB; one `INCRBY` on a ≤ 25 h `eem:v1:cw:<day>` key pipelined with each `SET`, 0 commands once exhausted until UTC midnight; reads continue); document and Form 4 cache TTL 7 days → 24 h (raw documents in memory 30 days → 24 h; Redis TTL capped at 24 h); `REDIS_MAX_VALUE_BYTES` 900 KB → 256 KiB, measured after gzip (values ≥ 8 KB stored compressed; the SEC ticker file ~520 KB → ~240 KB, still shared); a capacity error (`ERR DB capacity quota exceeded` / OOM) on a cache write stops only cache writes on that instance for 10 min ("redis full" in `/health`), while counters, the quota script, API keys and suppression keep their fail-closed handling (a capacity error there enters degraded mode with reason "redis full"). Cache write cost 1 → 2 commands (3 for an instance's first write of the day); refusals still 0.
  - *Security review (PR #3):* Redis TTLs capped at min(TTL, 24 h, next UTC midnight + 1 h), so stored cache data is bounded by about 2 days' write budget; default budget 150 → 64 MiB, each write counted as value + key + 96 B; bytes reserved locally before the write is sent (50 concurrent writes can't overspend); the budget counter is created by `SET NX EXAT` (TTL guaranteed, no separate `EXPIREAT`); gzip level 9 → 6 and no compression attempt for values > 20× the max; Redis cache bytes read count toward a call's actual cost (≤ 256 KiB per unit) to bound bandwidth; "budget exhausted" moved behind `HEALTH_SECRET` in `/health`; e2e quota test made deterministic.
  - *Security re-review (PR #3):* the budget check and the write are one atomic Lua script (`EVALSHA`/`EVAL` fallback: counter + size > budget → −1, nothing written; else `SET NX EXAT` counter, `INCRBY`, `SET EX` value), so the fleet can no longer overshoot the budget (cold instances started with an empty memo); refusals memoised until the UTC day ends; the first write of the day reads the counter (cold instances facing a full counter send no value); pending writes tracked separately (memo = max(known, fleet total + pending)); Redis read bytes counted with `Buffer.byteLength`; non-finite TTLs never reach Redis. Tests: 10 fresh instances × 50 concurrent writes against a full counter → 0 writes.

Security hardening (audit 2026-10-20).

- **Quotas (C1):** cost-weighted per-IP and per-API-key limits on the HTTP endpoint (initial defaults, now superseded by the re-review *H2* entry below: anonymous 30 units/min and 300/day per IP plus 1,500/day per /24 network and 2,000/day for all anonymous callers; API key 120/min, 2,000/day), with `RATE_LIMITED` errors carrying `retry_after_seconds` and a key-request hint. Self-verifying API keys (`scripts/create-key.ts`, `scripts/delete-key.ts`, `REVOKED_KEY_IDS`). JSON-RPC batches rejected; insider fan-out capped at 20 filings, entity lookups at 5 states.
- **SEC limiter (C2):** two-stage limiter (local spacing + atomic Upstash token bucket, default 6 rps, max 8) that fails closed when no token is available in time; also applied to state portals. On Redis errors it does not fail closed but degrades to a reduced local rate (`DEGRADED_SEC_RPS`, see *M1* below; state portals 1 rps) and refuses calls only when that rate is `0`. Raw documents are no longer stored in Redis; cache keys are normalized.
- **SSRF / size (H1, L2):** strict EDGAR Archives URL validation, 15 MB streaming cap, manual redirects with host re-check.
- **Privacy (H3):** individual registered agents withheld unless `include_agent_details: true`; suppression list (`scripts/suppress.ts`); NY service-of-process field.
- **Prompt injection (H4):** filing text wrapped in untrusted-content markers with `untrusted_content: true`; zero-width/bidi characters stripped.
- **M1–M5, L1–L5:** `SOCRATA_APP_TOKEN` support and less overfetch; `findFiling` capped at 8 pages, failed ticker resolves not cached in Redis; `/health?deep=1` gated by `HEALTH_SECRET`; node server binds 127.0.0.1 with Host/Origin checks; 64 KB body cap; generic client errors with log reference ids; SEC tools refuse to run without a real `SEC_USER_AGENT`.
- **Data minimisation of rate-limit state:** Redis holds only integer counters with TTL = window (per-minute 70 s; daily per-IP, per-/24 and per-key 25 h); per-tool usage hashes and the 35-day key retention are removed. IP hashes use a daily-rotating keyed hash (keyed with `IP_HASH_SALT`). Cache keys are hashed, so Redis key names never contain URLs or tool arguments. Error logs mask query strings, IPs and emails. A quota check that errors or takes longer than 3 s (`QUOTA_TIMEOUT_MS`) does not fail closed with the Upstash store: the instance enters degraded mode and enforces the same limits in memory (see *B1* below); only a custom non-Redis quota store fails closed (`RATE_LIMITED`, scope `backend`). `create-key.ts` stores no label, name or contact.
- **Review follow-up (MCP SEC Security, PR #2):**
  - *Redis command budget (B1):* all daily quota counters in one `EVALSHA` (no per-tool `HINCRBY`; billed counts in the re-review entry below); blocks memoised in memory until the window ends (repeat blocked calls: 0 commands); self-verifying API keys `eem_<id>_<HMAC>` (forged/random keys: 0 commands) plus an in-memory limiter on failed key attempts (HTTP 429); degraded mode when Redis is unavailable (local quotas, no Redis cache, reduced SEC rate via `DEGRADED_SEC_RPS`, see *M1* below) instead of an outage. Command counts asserted in `tests/budget.test.ts`.
  - *Privacy (B2):* the server refuses to start with Redis configured and `IP_HASH_SALT` missing, the old default or shorter than 32 chars; key records hold no owner name or contact; `scripts/delete-key.ts` deletes a key and its counters; per-key counters 25 h, minute counters 70 s; no `u:` usage data.
  - *Fair use (H-a, L-b):* global daily cap for all anonymous callers (2,000 units); 2 of 6 SEC req/s reserved for API-key callers; max 4 concurrent upstream fetches per client. Defaults: network cap 3,000 → 1,500, key 5,000 → 2,000 units/day.
  - *Agent classification (M-a):* names count as organizations only with a legal-form suffix or as a known agent service; everything else (including CO/PA/PC endings) is an individual.
  - *Agent details (M-b):* `include_agent_details` only for API-key callers; principal/mailing addresses and NY location name withheld when the agent or service-of-process contact is an individual.
  - *Suppression (M-c):* normalized entity ids; suppressed names matched in entity name, NY location name and addresses; state lookups refused on a cold start when the list cannot be loaded.
  - *Untrusted text (M-d):* random per-response marker nonce (`untrusted_marker_id`); Unicode tag characters stripped; entity names/addresses, Form 4 names/remarks/footnotes and XBRL labels/descriptions cleaned and listed in `untrusted_fields`.
  - *L-a, L-c, L-d:* client IP from `x-vercel-forwarded-for`, then XFF, then `x-real-ip`; costs `get_filing_document` 4/10, `get_insider_trades` 6 + limit (max 26), `list_filings` 6 with paging; SEC token bucket refills smoothly (1 token / 167 ms, burst 2).
- **Re-review follow-up (MCP SEC Security, d0e4cb4):**
  - *B1:* the last known value of every daily counter (own, /24, global) is memoised until UTC midnight; a call whose cost exceeds the remaining allowance is refused locally at 0 commands (fixes "299/300 + cost-10 spam = 2 commands per call").
  - *H1:* billed-command counts documented honestly (script-internal commands included): anonymous allowed quota check 4, keyed 2, refused-by-memo 0; whole warm call 4, cold 1-SEC-request call 10. Per-minute counters moved to memory (fewer counters); `EXPIRE` only when `INCRBY` creates the key; no `MGET`.
  - *H2:* reserve-then-refund (actual cost = upstream requests, min 1; refunds folded into the next `INCRBY`, 0 extra commands); per-/24 cap ≤ 10% of the global anonymous budget; soft global cap with a 10-unit per-IP trickle up to a hard ceiling (1.5×). New, lower defaults: anonymous up to 60/IP, 60 per /24, 600 soft / 900 hard global, key 500 units/day.
  - *M1:* degraded mode: anonymous callers cache-only; API-key callers at a reduced SEC rate (`DEGRADED_SEC_RPS`, `0` = refuse).
  - *M2:* `REVOKED_KEY_IDS` denylist; keys accepted unverified in degraded mode are not trusted for `include_agent_details`.
  - *M3:* `API_KEY_SECRET` (≥32 chars, ≠ `IP_HASH_SALT`) required with Redis; no longer derived from `IP_HASH_SALT`.
  - *Low:* TTL set atomically when a counter is created; stricter classification of Redis limit errors; LRU for memoised state; variation selectors stripped; suppressed names inside entity names withhold the name.
  - Docs: "Required configuration before resuming the hosted deployment".
- **Breaking:** `IP_HASH_SALT` and `API_KEY_SECRET` (≥32 chars) are required when Redis is configured. API keys minted by earlier 0.2.0 previews (`eem_<32 chars>`) are no longer valid. Setting `MCP_API_KEYS` no longer makes keys mandatory; use `MCP_REQUIRE_API_KEY=1`. `SEC_USER_AGENT` is now required for SEC tools. Default `SEC_MAX_RPS` 8 → 6.
